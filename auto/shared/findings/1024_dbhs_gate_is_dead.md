# 2026-10-24 判决性发现: 零初始化"加性门控"是死的, 乘法门控才能学

**作者**: Doubao(handover) | **严重度**: 最高(推翻本项目管理以来的多数结论)
**证据脚本**: `Doubao/Classification/experiments/diag_gate_effect.py`

## 1. 指标
对每个 checkpoint, 用 9 张真实 val 图前向, 对每个门控挂 hook, 计算

    rel = mean|y - x| / mean|x|        (门控对特征流的相对扰动)

加性门控 `y = x + gamma*BN(branch(x))` 与乘法门控 `y = x*(1+tanh(a)) + b`
可以放在同一把尺子上比。

## 3. 为什么(解析解释, 与实测吻合)
gamma 初值 0, AdamW lr=1e-4, 每步更新量级 ~1e-4。

    随机游走 N 步的标准差 = lr*sqrt(N) = 1e-4*sqrt(3300) ≈ 5.7e-3

实测 mean|gamma| = 2e-3 ~ 7e-3 —— **完全吻合**。也就是说 gamma 从未"梯度下降",
只是随机游走。加性门控要求"分支先有用才开门", 但分支在开门前不可能有用 => 死锁。

乘法门控没有这个死锁:
    dL/da = dL/dy * x * sech^2(0)
是**主路同阶的一阶梯度**, 不需要等分支先有用。

## 4. 后果: 本项目管理以来的结构结论全部作废
过去 ~40 个"结构变体"测出的"无增益/证伪", 实际测的是**一个 0.3%~2% 权重的旁路**,
而不是那个机制本身。包括但不限于:
- 频域/小波族全灭 (workbuddy W1-W4)
- SE / PFESA / 条带 / 边缘分支 / layer2 插入
- zcode 的 rates 空间封闭、单/双位置消融
- 豆包 be/bf 七个库模块"无增益"

**这不代表那些机制无效, 只代表它们在被打开之前就被判了死刑。**
dil234 之所以是唯一"有效"的结构, 恰恰因为它的 rel 到 1.4~2.1%(最高的一档加性门控)。

## 5. 但"打开得多"不等于"涨点"——单种子排序就是噪声
| 模型 | rel@gate3 | val_best(seed42) | Δ vs van60 |
|---|---|---|---|
| film4 | (12.4% @l4) | 0.8591 | **-1.05pt** |
| filmdw34 | 26.85% | 待出 | - |
| film34 | 4.68% | 0.8795 | +0.99pt |
| db_msam | **1.08%** | **0.8857** | **+1.61pt** |

- film4 扰动 12.4% 却掉 1pt(过度调制), 说明存在最优点;
- db_msam 只扰动 1.08% 却"涨" 1.61pt —— **这在机制上不可能**, 只能说明
  **单种子 + 538 样本 val 的噪声(~1.5pt SE)完全支配了排序**。

## 6. 因此协议必须换(已在执行)
1. 筛选不做单种子定论; 晋级需 3 种子配对均值。
2. 决赛用 5 折交叉验证(覆盖 2924 张, SE 1.5->0.66pt), 且 checkpoint 只在
   inner-split 上选, 不在 test fold 上选。
3. 新设计一律用**乘法/结构性改动**(初始化即改变函数), 不再用零初始化加性挂载。
