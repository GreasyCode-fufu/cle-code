# 【用户最高指示·转发】性能优先，大胆突破，勿墨守成规

- 时间：2026-10-24
- 来源：任务授权方（用户）当面向 Doubao 明确指示，由 Doubao 转达 **zcode / Workbuddy**
- 优先级：最高（任务授权层，与 shared/README 同权）

## 一、核心指示（原话精神）
> 任务核心是设计一个**性能上最优的网络结构**，只要性能好就行；不要墨守成规，要**突破性能上限**。

- 性能是第一目标，结构形态、技术路线不限。
- 不要被"已证伪清单"和现有 dil234 范式框住，不要只在现有模块上做小修小补（调膨胀率/加分支/挪位置这类增量）。
- **鼓励大胆设计全新结构、新机制，允许颠覆当前方案；高风险高回报的方向也值得开。**

## 二、创新手段全解锁（请大胆用足）
- 任意网络结构：**不必局限于零初始化门控 / 多尺度膨胀这一条路线，可另起炉灶**（新骨干内部结构、新注意力、新融合方式、新特征金字塔、频域/空间混合、大核/可变形/重参数化等）。
- 损失函数、数据增强、训练调度、TTA、集成、类别校准、输入分辨率等全部合法。
- 不要因为"看起来像某个已证伪模块"就放弃——只要机制不同、有依据，就用对照实验说话。
- 提醒：非零初始化的插入会在 epoch0 改变特征分布（历史上多掉点），**可以试，但必须有对照证明它真的赢**，而不是默认安全。

## 三、唯一不可让步的底线（目的是让"高分"可信，不是限制创新）
1. 性能以 **test 集 macro-F1** 判定，**val 只用于选模/拟合校准**，严禁 test 选模、用 test 调参或反复看 test 改结构。
2. 申报成功必须**多种子（best-of-3，种子 42/43/44）同种子集配对**，单种子的高分不构成突破。
3. 训练公平基线（AdamW lr1e-4 wd0.05 / Cosine / AMP / batch32 / 300ep / 选模规则）保持不变以保证三方可比；在此之上叠加的结构/损失/增强等 recipe 必须注明。
4. 失败、掉点如实记录，禁止只报喜。
5. 协作规则不变：只改自己工作区、单 Agent 并发 ≤2、新模型注册名各自前缀、所有改动 git 提交。

## 四、行动建议

- 突破性想法可在 shared/brainstorm.md 或本公告下追加讨论，注明机制和预期，减少撞车。
- 撞车规则不变：时间戳先者认领。
